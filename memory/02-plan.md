## 2. 工程策略（**推定，待确认**）
- **从零新建工程**，仅依赖 Fabric API（不加 Coth Config 等第三方库）。
- 不复制 Apophis 工程：Apophis 是 Meteor 客户端 addon（Orbit 事件总线），与「服务端权威内容模组」架构不匹配。
- 配置：JSON/TOML 文件 + /scp 命令；不做图形化配置。
- SCP 扩展：代码级注册（基类/接口/钩子/注册表）。
- 质量：关键机制 GameTest + 设计/维护文档。
- 联机：服务端权威逻辑，单机/LAN/专用服三态都需验证。

## 3. 里程碑（用户已确认三刀切法）

### M1 地基
- 交付物：
  - 新工程可编译、可加载（fabric.mod.json / entrypoint / 配置骨架）
  - Jigsaw 站点生成：≥1 个站点类型 + 房间池（数量上限需写入时间盒）+ 主世界分布规则
  - 收容单元 + 操作终端方块与方块实体（拆解 = 泄压）
  - SCP 注册层：基类 / 接口 / 注册表 / 事件钩子
  - 配置文件加载 + /scp 命令骨架（locate / event / spawn / status 方向）
- 验收：新世界能用命令找到并进入设施，看到收容单元与终端，拆掉收容单元会泄压（此阶段可以还没有 SCP）

### M2 事件链
- 交付物：
  - 事件状态机：触发 → 预警 → 突破 → 扩散 → 重新收容 → 结算
  - 呈现层：Boss 条 / 警报音 / 提示文本
  - 混合触发（玩家行为为主 + 低概率环境诱因）
  - SCP-173 参考实现（观察冻结 / 瞬移 / 扭颈）
  - 突破后的世界级追猎与再收容路径
  - 事件统计记录
- 验收：完整跑通一次「触发 → 预警 → 突破 → 173 追猎玩家 → 用收容单元重新收容 → 结算有记录」

### M3 打磨
- 交付物：
  - 统计持久化与查看
  - 联机三态验证（单机 / LAN / 专用服务器）
  - 关键机制 GameTest
  - 设计 / 维护文档
  - 配置项完善、性能与存档健壮性
- 验收：3 人 LAN 一局无致命 bug；GameTest 全绿；文档可让接手者在无口头指导下继续开发
